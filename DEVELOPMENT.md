# Developing Campfiremons

How the pack is built, tested, released and hosted. Players only need [README.md](README.md); the design brief
(stages, gating, mod list, update path) is [DESIGN.md](DESIGN.md).

This repo is a [packwiz](https://packwiz.infra.link/) pack. Mods are stored as small `.pw.toml`
metadata files (download URL + hash), never as jars.

## Layout

| Path | What |
|---|---|
| `pack.toml`, `index.toml` | packwiz pack metadata (`index.toml` is generated by `packwiz refresh`) |
| `mods/`, `resourcepacks/`, `shaderpacks/` | one `.pw.toml` per file |
| `config/` | configs we ship; `config/defaultoptions/` holds the official pack's first-launch defaults |
| `kubejs/` | our scripts (`startup_scripts/`, `server_scripts/`, `client_scripts/`) and datapack files |
| `tools/` | dev scripts (not shipped to players, see `.packwizignore`) |
| `tools/release/` | `build.py` (the release zips) and the server starter's `start.sh` |
| `.github/workflows/` | `release.yml` publishes a GitHub Release per `vX.Y.Z` tag; `check.yml` fails on a stale `index.toml` |
| `README.md` | the player-facing page: install, joining, how the pack plays |
| `CHANGELOG.md` | one section per version, used as the release notes |

## Dev setup (once)

```sh
go install github.com/packwiz/packwiz@latest   # installs ~/go/bin/packwiz
sh tools/setup-dev-instance.sh                 # creates the "Campfiremons Dev" Prism instance
```

Restart Prism if the instance doesn't show up.

## Dev loop

- Press Play on **Campfiremons Dev**. Its pre-launch hook (`tools/dev-prelaunch.sh`) runs
  `packwiz refresh` and then syncs mods/configs from this repo into the instance.
- `kubejs/` and `config/ftbquests/` in the instance are symlinks to this repo. Script edits are
  live: `/reload` re-runs server scripts, and `/kubejs reload startup` re-runs startup scripts
  (where the Cobblemon gating lives). The in-game quest editor saves straight into git.
- Logs (KubeJS 2101 writes them under the instance's `logs/`, not `kubejs/logs/`):
  `minecraft/logs/kubejs/startup.log`, `server.log`, `client.log`, and `minecraft/logs/latest.log`.

## Generated data

`tools/gen_finds.py` owns the stage advancements, the "found" advancements and the stage-finds loot modifiers
under `kubejs/data/` (see the list at the top of the script). Don't hand-edit those JSON files: change the
config in the script, then run `python -I tools/gen_finds.py` and `packwiz refresh`.

The quest book in `config/ftbquests/quests/` was generated **once** by `tools/gen_quests.py` (one chapter per
stage). From now on it is edited in game: open the book, toggle edit mode (needs op), and FTB Quests saves straight
into this repo through the dev-instance symlink. Re-running the script needs `--force` and discards those edits.

`tools/gen_shop.py` owns `config/cobbledollars/default_shop.json` (the default shop minus the
Master Ball); re-run it after updating CobbleDollars.

`tools/gen_drops.py` owns every `species_additions` file under `kubejs/data/` (drop fixes for mods that replace
Pokémon drop tables, plus egg drops). Re-run it after updating Cobblemon or any mod that ships species_additions.

## Testing stages

A player's stage is their highest `campfiremons:stage/N` advancement. With vanilla `/advancement`:

```
/advancement grant @s until campfiremons:stage/4    # stages 1–4 (the advancement + its parents)
/advancement revoke @s from campfiremons:stage/1    # clears all stages (the advancement + its children)
/advancement grant @s only campfiremons:bypass      # admin bypass for every lock
```

Don't use `through` for this: it also grants all the *children*, i.e. every later stage up to Champion.

Local test fixtures live in `tools/testpacks/` (datapacks, never shipped). Copy them into a dev world with
`sh tools/install-testpack.sh ["<world folder>"]` (default: the newest world), then in game `/reload` and
`/datapack enable "file/<pack>"`; `/datapack disable` turns one off again.

- `campfiremons-test`: the `campfiremons_mega_test` RCT trainer (Radical Red series, optional, never spawns)
  leading with Mega-ready Manectric and a Primal Kyogre. Summon with `/rctmod trainer summon campfiremons_mega_test`.
- `campfiremons-weak-gyms` (generated by `tools/gen_weak_gyms.py`): every stage trainer (Brock … Champion Terry)
  fields one Lv5 Magikarp with Splash, so stage progression can be tested with real wins. Disable it to fight the
  real Radical Red teams.

## Adding or updating mods

```sh
packwiz mr add <modrinth-slug>        # prefer Modrinth
packwiz cf add <curseforge-slug>      # only if the mod isn't on Modrinth
packwiz update <name>                 # bump one mod
```

Resource packs we turn on by default are listed by file name in `config/defaultoptions/options.txt`
(`resourcePacks`, applied on a player's first launch). After `packwiz update` renames one (e.g. the RCT trainer skins,
`RCT Trainers+ [1.7] v2.2.zip`), update that entry too.

Modrinth/CurseForge dependency lists can be incomplete (Chipped needs Resourceful Lib and Athena but doesn't say so).
After adding mods and syncing the dev instance, check what the jars themselves require before launching:

```sh
python -I tools/check_deps.py        # lists required mod ids no installed jar provides
python -I tools/check_versions.py    # flags Modrinth builds that aren't for our Minecraft version/loader
python -I tools/check_biomes.py      # for biome mods: which new biomes get no Cobblemon spawns
```

Re-importing the official pack's files at their exact versions (after an official update):

```sh
python -I tools/import_mrpack.py <official.mrpack>   # existing .pw.toml files are skipped
packwiz refresh
```

Official-pack overrides that are deliberately **not** included: the bundled tutorial world, the
FancyMenu title-screen branding/assets, the CraftPresence (Discord status) config and the official tips pack.
We ship only `config/fancymenu/options.txt`, with `modpack_mode` on and the editing overlay off, so players
get the plain title screen with no FancyMenu setup prompts.

## Releasing

`main` is work in progress; players and the server pull the `release` branch.

1. On `main`: bump `version` in `pack.toml`, add a `## vX.Y.Z` section to `CHANGELOG.md`, run `packwiz refresh`,
   and commit. `python3 tools/release/build.py` builds the zips into `dist/` if you want to check them first.
2. Ship it:
   ```sh
   git switch release && git merge --ff-only main && git tag vX.Y.Z
   git push origin main release vX.Y.Z && git switch main
   ```
3. CI (`.github/workflows/release.yml`) publishes the GitHub Release with the Prism zip and the server starter.
   Players get the update on their next Play, and the server on its next restart.

Changing the Minecraft or NeoForge version also needs action outside the pack: players change the NeoForge version
in Prism (**Edit → Version**) or re-import, and on the server `NEOFORGE_VERSION`/`NEOFORGE_SHA256` in
`tools/release/server/start.sh` must be updated (`build.py` refuses to build until they match `pack.toml`), then the
new `start.sh` uploaded.

## Running the server

The host needs Java 21, 10–12 GB of RAM, SFTP access and an editable startup command (DESIGN.md §8).

1. Upload `campfiremons-<version>-server.zip` from the latest release and unzip it in the server folder (once).
2. Set the startup command to `MEMORY=10G sh start.sh`, with `MEMORY` 1–2 GB below the plan's RAM.
3. Start the server. `start.sh` installs NeoForge, syncs the pack, then the server stops to ask for the EULA:
   set `eula=true` in `eula.txt` and start again.
4. In the console: `op <you>`, then `whitelist add <name>` for each player (the whitelist is on by default).

Every restart pulls the latest release. On a host without a custom startup command: unzip the starter on your PC,
run `sh start.sh --sync-only` there (needs Java 21), upload the whole folder over SFTP, and set the host to start
NeoForge's own `run.sh`. Repeat that for each update.
