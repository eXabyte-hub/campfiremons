# Campfiremons

A Cobblemon-first NeoForge 1.21.1 modpack for our friend group, built on the
[Cobblemon Official Modpack [NeoForge]](https://modrinth.com/modpack/cobblemon-neoforge) 1.8.4.
See `DESIGN.md` for the design brief (stages, gating, mod list, update path).

This repo is a [packwiz](https://packwiz.infra.link/) pack. Mods are stored as small `.pw.toml`
metadata files (download URL + hash), never as jars.

## Layout

| Path | What |
|---|---|
| `pack.toml`, `index.toml` | packwiz pack metadata (`index.toml` is generated by `packwiz refresh`) |
| `mods/`, `resourcepacks/`, `shaderpacks/` | one `.pw.toml` per file |
| `config/` | configs we ship; `config/defaultoptions/` holds the official pack's first-launch defaults |
| `kubejs/` | our scripts (`startup_scripts/`, `server_scripts/`, `client_scripts/`) and datapack files |
| `tools/` | dev scripts (not shipped to players, see `.packwizignore`) |

## Dev setup (once)

```sh
go install github.com/packwiz/packwiz@latest   # installs ~/go/bin/packwiz
sh tools/setup-dev-instance.sh                 # creates the "Campfiremons Dev" Prism instance
```

Restart Prism if the instance doesn't show up.

## Dev loop

- Press Play on **Campfiremons Dev**. Its pre-launch hook (`tools/dev-prelaunch.sh`) runs
  `packwiz refresh` and then syncs mods/configs from this repo into the instance.
- `kubejs/` and `config/ftbquests/` in the instance are symlinks to this repo. Script edits are
  live: `/reload` re-runs server scripts, and `/kubejs reload startup` re-runs startup scripts
  (where the Cobblemon gating lives). The in-game quest editor saves straight into git.
- Logs (KubeJS 2101 writes them under the instance's `logs/`, not `kubejs/logs/`):
  `minecraft/logs/kubejs/startup.log`, `server.log`, `client.log`, and `minecraft/logs/latest.log`.

## Generated data

`tools/gen_finds.py` owns the stage advancements, the "found" advancements and the stage-finds loot modifiers
under `kubejs/data/` (see the list at the top of the script). Don't hand-edit those JSON files: change the
config in the script, then run `python -I tools/gen_finds.py` and `packwiz refresh`.

## Testing stages

A player's stage is their highest `campfiremons:stage/N` advancement. With vanilla `/advancement`:

```
/advancement grant @s until campfiremons:stage/4    # stages 1–4 (the advancement + its parents)
/advancement revoke @s from campfiremons:stage/1    # clears all stages (the advancement + its children)
/advancement grant @s only campfiremons:bypass      # admin bypass for every lock
```

Don't use `through` for this: it also grants all the *children*, i.e. every later stage up to Champion.

Local test fixtures live in `tools/testpacks/` (datapacks, never shipped). Copy them into a dev world with
`sh tools/install-testpack.sh "<world folder>"`, then `/reload`; toggle one with
`/datapack enable|disable "file/<pack>"`.

- `campfiremons-test`: the `campfiremons_mega_test` RCT trainer (Radical Red series, optional, never spawns)
  leading with Mega-ready Manectric and a Primal Kyogre. Summon with `/rctmod trainer summon campfiremons_mega_test`.
- `campfiremons-weak-gyms` (generated by `tools/gen_weak_gyms.py`): every stage trainer (Brock … Champion Terry)
  fields one Lv5 Magikarp with Splash, so stage progression can be tested with real wins. Disable it to fight the
  real Radical Red teams.

## Adding or updating mods

```sh
packwiz mr add <modrinth-slug>        # prefer Modrinth
packwiz cf add <curseforge-slug>      # only if the mod isn't on Modrinth
packwiz update <name>                 # bump one mod
```

Re-importing the official pack's files at their exact versions (after an official update):

```sh
python -I tools/import_mrpack.py <official.mrpack>   # existing .pw.toml files are skipped
packwiz refresh
```

Official-pack overrides that are deliberately **not** included: the bundled tutorial world, the
FancyMenu title-screen branding/assets, the CraftPresence (Discord status) config and the official tips pack.
We ship only `config/fancymenu/options.txt`, with `modpack_mode` on and the editing overlay off, so players
get the plain title screen with no FancyMenu setup prompts.
